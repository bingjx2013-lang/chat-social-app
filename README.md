# 微聊 · 简单聊天社交应用

一个基于 Node.js、Express、Socket.IO、SQLite 和 WebRTC 的中文网页聊天项目，可部署到公网。项目提供一对一私聊和浏览器内音视频通话；不是已经上线的托管服务，公网地址需要由部署者创建。

## 已实现功能

- 用户注册、登录、退出，密码使用 bcrypt 哈希存储；认证使用服务端可撤销会话和安全 Cookie。
- 通过账号搜索用户，发送好友申请，接受或拒绝申请。
- 好友之间的实时文字消息，聊天记录保存到 SQLite，页面展示最近 100 条记录。
- 发送图片、视频、音频及普通文件；单个文件最大 50 MB，下载和预览需要登录并且仅允许聊天双方访问。
- 一对一语音通话、视频通话、接听/拒绝、挂断、麦克风静音和摄像头开关。
- 自适应手机和桌面浏览器的中文界面。

## 本地运行

需要 Node.js 20 或更新版本。

```bash
npm install
cp .env.example .env
```

然后运行：

```bash
npm start
```

浏览器打开 `http://localhost:3000`。可以先注册两个账号，在两个浏览器或隐私窗口中登录，互相添加好友来测试聊天和通话。

## 部署到公网（Render 示例）

1. 把整个项目提交到自己的 GitHub 仓库。
2. 在 Render 创建 **Web Service**，关联该仓库。
3. Build Command 填 `npm install`，Start Command 填 `npm start`。
4. 设置环境变量：
   - `NODE_ENV=production`
   - `DATA_DIR=/var/data`
5. 在服务中挂载持久化磁盘到 `/var/data`。SQLite 数据库和上传的文件都保存在那里；没有持久化存储时，部分主机重启或重新部署会清空本地文件。Render 的磁盘功能和方案限制请以其最新文档为准。
6. 等部署完成，使用平台分配的 HTTPS 域名访问。摄像头和麦克风通常要求安全上下文（HTTPS 或 localhost）。

## 音视频通话说明

通话通过 WebRTC 连接，Socket.IO 只负责呼叫邀请和交换连接协商信息。当前默认使用公共 STUN 服务；某些 NAT、运营商网络或企业防火墙环境下，单靠 STUN 不能建立通话，建议为正式公网服务配置 Coturn TURN 中继。

可以在 `.env` 设置：

```bash
TURN_URLS=turn:turn.example.com:3478,turns:turn.example.com:5349
TURN_SHARED_SECRET=替换成与Coturn配置相同的REST共享密钥
```

服务会通过 Coturn REST API 方式生成有效期一小时的短期凭据。请先正确配置 Coturn 的 `use-auth-secret` / `static-auth-secret` 和 TLS/防火墙端口；不要把 TURN 共享密钥写进前端代码或提交到仓库。TURN 主机名需要替换成自己的真实域名。

## 当前版本的边界与上线前事项

- 这是可运行的基础版本，不包含群聊、消息撤回、已读回执、密码找回、邮箱/短信验证、推送通知、管理员后台或端到端加密。
- 传输安全依赖公网 HTTPS/WSS。聊天内容目前保存在服务器 SQLite 中，服务端可以读取；**不能把它当作端到端加密通讯工具**。
- 上传文件暂存在服务器磁盘，建议为正式服务配置文件数量/总容量配额、病毒扫描、备份和对象存储；当前单文件限制为 50 MB。
- 上线前应配置自有域名、持久化数据库和附件存储、TURN 中继、日志监控、备份、滥用举报/封禁和更全面的限流策略。
- 该版本适合做 MVP 或小规模单实例部署。SQLite + 本地附件目录适合单实例；多实例扩容时应迁移到托管数据库和共享对象存储，并为 Socket.IO 配置共享适配器。
- 目前账号仅使用用户名和密码，账号不能用于证明真实身份。请不要上传敏感或机密资料。

## 关键安全措施

- 密码哈希、服务端会话鉴权、安全 Cookie、同源请求检查和登录接口限流。
- Socket.IO 使用可撤销服务端会话认证；服务端根据登录身份确定消息发送人，不能由客户端伪造发送人 ID。
- 服务端验证好友关系；文件通过鉴权 API 读取，附件随机命名，不作为公开静态文件目录暴露。
- 限制上传大小并拒绝常见可执行文件扩展名；Helmet 设置常用安全响应头。

在有真实用户和公开访问量之前，仍应完成正式安全测试与隐私评估。
